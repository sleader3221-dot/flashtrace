# FlashTrace rules

Generated by `python -m tools.gen_docs` from the rule registry and
`src/flashtrace/data/attck_ics_map.yaml`. Do not edit by hand.

Every finding cites evidence (absolute offset, length, partition, SHA-256 of the
exact bytes). Secret values are redacted unless `--reveal-secrets` is given; the
SHA-256 of the unredacted value is always stored.

## CORE.PRESENT

**Severity:** medium · **ATT&CK for ICS:** none — needs review

**Coredump present.** The coredump partition is not erased: the device crashed at least once and saved a core dump (task stacks/memory, possibly containing secrets).

**False positives:** Crashes during development are common; still worth retrieving for analysis.

**Mapping note:** Crash artefact; may contain memory with secrets.

## FS.SUSPICIOUS_FILE

**Severity:** medium · **ATT&CK for ICS:** none — needs review

**Suspicious file in filesystem.** A SPIFFS/LittleFS file is a key/cert/script by extension (.pem .key .der .crt .p12 .pfx .sh .py .lua), is an executable (ELF or ESP image), or its content triggers a SEC.* detector.

**False positives:** Web UIs legitimately ship URLs and CA certificates; review the reasons list.

**Mapping note:** Scripts could relate to T0853 Scripting; keys/certs to credential exposure.

## IMG.CHECKSUM_BAD

**Severity:** high · **ATT&CK for ICS:** T0857 proposed — needs review

**App image checksum invalid.** The XOR checksum (seed 0xEF) stored after the segments does not match the segment data: the image was modified or corrupted.

**False positives:** Partially written OTA slots (interrupted update) also fail.

**Mapping note:** Modified or corrupted image; proposed T0857 System Firmware when tampering is confirmed.

## IMG.NO_APP_DESC

**Severity:** medium · **ATT&CK for ICS:** none — needs review

**App image without esp_app_desc_t.** An app partition holds a parseable image but no esp_app_desc_t (magic 0xABCD5432) at the start of any segment: not built by the ESP-IDF app build, or the descriptor was stripped.

**False positives:** Non-ESP-IDF toolchains (bare-metal, some Arduino/Rust builds) may legitimately omit it.

**Mapping note:** Non-ESP-IDF or stripped image.

## IMG.SHA256_BAD

**Severity:** high · **ATT&CK for ICS:** T0857 proposed — needs review

**App image SHA-256 invalid.** The appended SHA-256 does not match the image bytes: the image was modified after build or is corrupted.

**False positives:** Partially written OTA slots (interrupted update) also fail.

**Mapping note:** Modified or corrupted image; proposed T0857 System Firmware when tampering is confirmed.

## IMG.SLOT_DIVERGENCE

**Severity:** medium · **ATT&CK for ICS:** T0857 proposed — needs review

**OTA slots diverge.** Two OTA slots carry different project_name or idf_ver, or their versions are not monotonic with the OTA sequence (the most recently written slot has the lower semantic version) or jump by more than one major version.

**False positives:** Legitimate product renames or IDF upgrades between releases also fire; review the pair.

**Mapping note:** Proposed T0857 System Firmware; legitimate product changes also diverge.

## IMG.UNKNOWN_BUILD

**Severity:** high · **ATT&CK for ICS:** T0857 (confirmed)

**App image not in baseline set.** With --baseline images supplied, an app image whose SHA-256 (over the whole image incl. checksum and appended digest) matches none of them. Inactive without baselines.

**False positives:** Any legitimate build that was not added to the baseline set also fires.

**Mapping note:** T0857 System Firmware: device runs firmware that is not a known-good build.

## NVS.DELETED_SECRET

**Severity:** high · **ATT&CK for ICS:** none — needs review

**Deleted secret recoverable from NVS.** An ERASED NVS entry (bitmap 0b00) still holds a value whose key or content looks like a credential, token or key.

**False positives:** Key-name heuristics can match non-secret config (e.g. 'auth_mode'); values that are all 0x00/0xFF or shorter than 4 bytes are ignored.

**Mapping note:** Recoverable deleted secret; impact depends on what the secret unlocks.

## NVS.WIFI_CREDENTIALS

**Severity:** high · **ATT&CK for ICS:** none — needs review

**Wi-Fi credentials stored in NVS.** A station or soft-AP passphrase is present in the live nvs.net80211 namespace.

**False positives:** Open networks have no passphrase and do not fire. Factory test credentials still fire.

**Mapping note:** Exposed Wi-Fi passphrase enables network access; T0859 Valid Accounts or T0860 Wireless Compromise are candidates.

## OTA.INVALID_ACTIVE

**Severity:** high · **ATT&CK for ICS:** none — needs review

**Selected or latest OTA image is invalid.** Either the otadata entry with the highest sequence (the latest OTA) is INVALID/ABORTED and the device fell back, or the slot the bootloader will select holds no image or one that fails its checksum / SHA-256.

**False positives:** A legitimately rejected update (rollback working as designed) fires the first variant.

**Mapping note:** Failed/rejected update or broken active image.

## OTA.PENDING_VERIFY

**Severity:** low · **ATT&CK for ICS:** none — needs review

**Active OTA image awaiting verification.** The selected otadata entry is in ESP_OTA_IMG_PENDING_VERIFY: a new image booted but was never marked valid; with rollback enabled the next reboot marks it ABORTED.

**False positives:** Captured mid-update on a healthy device; usually transient.

**Mapping note:** Update state; usually benign.

## OTA.ROLLBACK_OR_DOWNGRADE

**Severity:** high · **ATT&CK for ICS:** T0857 proposed — needs review

**Active OTA slot is older than the inactive one.** The slot selected by otadata has a lower secure_version than another OTA slot, or a lower semantic version when both versions parse as semver: a rollback or forced downgrade.

**False positives:** A deliberate, operator-approved rollback also fires; secure_version anti-rollback would normally prevent the secure_version case on devices with it enabled.

**Mapping note:** Downgrade to older (possibly vulnerable) firmware; proposed T0857 System Firmware.

## PARSE.ANOMALY

**Severity:** low · **ATT&CK for ICS:** none — needs review

**Structural anomaly.** A parser met malformed or unexpected structure (truncation, bad magic, CRC mismatch, …) and recorded it instead of failing. Anomalies with a dedicated rule are excluded.

**False positives:** Normal wear (e.g. a FREEING NVS page) can produce low-value anomalies.

**Mapping note:** Structural anomaly.

## PT.MD5_MISMATCH

**Severity:** high · **ATT&CK for ICS:** none — needs review

**Partition table MD5 mismatch.** The MD5 entry of the partition table does not match the entries before it: the table was edited after it was generated.

**False positives:** Some very old ESP-IDF tables have no MD5 entry; absence is not reported, only mismatch.

**Mapping note:** Table edited after generation; tampering or corruption.

## PT.OUT_OF_BOUNDS

**Severity:** high · **ATT&CK for ICS:** none — needs review

**Partition beyond end of dump.** A partition extends past the end of the dump: the table is inconsistent with the flash size, or the dump is truncated.

**False positives:** A deliberately partial dump (e.g. only the first 2 MB read) also triggers this.

**Mapping note:** Inconsistent layout or truncated dump.

## PT.OVERLAP

**Severity:** high · **ATT&CK for ICS:** none — needs review

**Overlapping partitions.** Two non-empty partitions share flash addresses, which can hide data or let one partition overwrite another.

**False positives:** Rare in legitimate builds; gen_esp32part.py refuses overlapping layouts.

**Mapping note:** Inconsistent layout.

## SEC.API_KEY

**Severity:** high · **ATT&CK for ICS:** T0891 proposed — needs review

**API key or access token in flash.** An AWS access key ID (AKIA/ASIA + 16 chars) or a generic token (>= 32 base64/url-safe characters mixing upper, lower and digits with >= 4.0 bits/char entropy) is present.

**False positives:** Generic tokens can match random-looking identifiers; pure-hex strings (hashes) are excluded. AWS key IDs are reported with higher confidence.

**Mapping note:** Hardcoded API key/token in firmware; proposed T0891 Hardcoded Credentials (API keys are not interactive-session credentials in every case).

## SEC.CERT

**Severity:** info · **ATT&CK for ICS:** none — needs review

**X.509 certificate in flash.** A PEM certificate, or a DER certificate (ASN.1 SEQUENCE header that parses with cryptography), is present.

**False positives:** CA bundles legitimately contain many certificates; each distinct certificate is reported once.

**Mapping note:** Informational indicator.

## SEC.FLASH_ENCRYPTION_LIKELY

**Severity:** info · **ATT&CK for ICS:** none — needs review

**Flash encryption likely enabled.** No partition table magic at the expected offset and the region's Shannon entropy exceeds 7.5 bits/byte: the dump is most likely ciphertext, so FlashTrace skips structural parsing.

**False positives:** Random/garbage dumps (bad read, wrong offset) look the same.

**Mapping note:** Informational.

## SEC.HARDCODED_CREDENTIAL

**Severity:** high · **ATT&CK for ICS:** T0891 (confirmed)

**Hardcoded credential in flash.** A password/secret/token assignment (e.g. password=..., "pwd": ...) or URL userinfo (scheme://user:pass@) is embedded.

**False positives:** Placeholder values (changeme, %s, password, ****) and format strings are ignored.

**Mapping note:** T0891 Hardcoded Credentials: credentials embedded in firmware.

## SEC.MQTT_BROKER

**Severity:** medium · **ATT&CK for ICS:** none — needs review

**MQTT broker endpoint in flash.** An mqtt:// or mqtts:// URI, or a host:1883 / host:8883 endpoint, reveals the device's broker.

**False positives:** Example/test broker strings shipped in libraries also match; deduplicated by value.

**Mapping note:** Reveals the device's broker endpoint; reconnaissance value only.

## SEC.NO_FLASH_ENCRYPTION

**Severity:** medium · **ATT&CK for ICS:** none — needs review

**Flash encryption not enabled.** The partition table and at least one app image parse as plaintext, so anyone with physical access can read firmware, NVS and filesystems.

**False positives:** Fires on every plaintext dump by design (posture finding).

**Mapping note:** Posture weakness; enables offline extraction of firmware and data.

## SEC.NO_SECURE_BOOT

**Severity:** medium · **ATT&CK for ICS:** none — needs review

**No Secure Boot V2 signature on any app.** No app image has a Secure Boot V2 signature block (magic 0xE7, version 0x02/0x03) at the first 4 KB boundary after the image: images are unsigned (structural check only).

**False positives:** Secure Boot V1 (ESP32 ECO<3) uses a different scheme and is not detected here.

**Mapping note:** Posture weakness; enables T0857 System Firmware modification but is not itself an adversary technique.

## SEC.PRIVATE_KEY

**Severity:** critical · **ATT&CK for ICS:** none — needs review

**PEM private key in flash.** A PEM-armoured private key block (RSA/EC/DSA/OpenSSH/PKCS#8, incl. ENCRYPTED) is present in an app image, NVS value or filesystem file.

**False positives:** Test vectors and example keys compiled into firmware still fire; the key is exposed either way.

**Mapping note:** Private key material at rest; could enable impersonation or TLS interception (T0830 candidate).

## SEC.URL

**Severity:** info · **ATT&CK for ICS:** none — needs review

**URL in flash.** An http:// or https:// URL is present (update servers, APIs, telemetry endpoints).

**False positives:** Documentation/vendor URLs are common; this is an informational indicator, deduplicated by value.

**Mapping note:** Informational indicator.

## DIFF.* (flashtrace diff)

Emitted only by `flashtrace diff dumpA dumpB`. Evidence points into the dump the
bytes come from (`detail.evidence_dumps`).

| Rule | Severity | Meaning |
|---|---|---|
| `DIFF.APP_DESC` | medium | App descriptor changed |
| `DIFF.FS_ADDED` | info | File added |
| `DIFF.FS_CHANGED` | info | File changed |
| `DIFF.FS_REMOVED` | info | File removed |
| `DIFF.NVS_ADDED` | info | NVS key added |
| `DIFF.NVS_CHANGED` | info | NVS value changed |
| `DIFF.NVS_REMOVED` | info | NVS key removed |
| `DIFF.OTA_STATE` | low | OTA selection/state changed |
| `DIFF.PARTITION_CHANGED` | info | Partition contents changed |
| `DIFF.PARTITION_TABLE` | medium | Partition table changed |
